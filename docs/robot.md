# Робот: xArm 7

## Коротко про руку

| Параметр | Значення |
| --- | --- |
| Модель | UFACTORY xArm 7 |
| Ступені свободи | 7 |
| Вантажопідйомність | 3.5 кг |
| Досяжність | 700 мм |
| Повторюваність | ±0.1 мм |
| Макс. швидкість TCP | 1 м/с (ми працюємо на **≤ 100 мм/с**) |
| Підключення | Ethernet до контролера (control box), статичний IP |
| SDK | [`xarm-python-sdk`](https://github.com/xArm-Developer/xArm-Python-SDK), Python 3.10+ |

Перед першим запуском перевірити в xArm Studio: версію прошивки, налаштовані TCP-офсет і вагу захвату,
безпечні межі (safety boundary).

## Що робот має вміти

Бот рухає лише **своїх воїнів**, тож усі задачі зводяться до одного примітиву:

```text
pick(точка A) → place(точка B)
```

| Дія гри | Що робить робот |
| --- | --- |
| `Recruit(clearing, n)` | n разів: запас → вільне місце в галявині |
| `Move(src, dst, n)` | n разів: воїн у `src` → вільне місце в `dst` |
| Втрати бота в бою | n разів: воїн у галявині → запас |

**Запас** — лоток або коробка у фіксованому місці біля дошки, з якого робот бере воїнів.
Найпростіше зробити його 3D-друкованим лотком з гніздами, тоді робот завжди знає, де лежить наступний воїн,
і зір для запасу не потрібен.

## Траєкторія одного pick & place

```text
       safe_z (напр. +80 мм над столом)
  ─────●──────────────────────●─────
       │                      │
       ▼ approach_z (+20 мм)  ▼
       │ повільно             │ повільно
       ▼ grasp_z              ▼ release_z
     [pick]                 [place]
```

1. Над точкою на висоті `safe_z`, захват відкритий.
2. Повільно опуститися до `grasp_z`, закрити захват.
3. Піднятися до `safe_z` і перейти до точки place.
4. Повільно опуститися до `release_z` (на 1–2 мм вище за стіл), відкрити захват.
5. Піднятися до `safe_z`.

Орієнтація інструменту завжди «вниз». Кут повороту навколо Z підбираємо так, щоб пальці не зачіпали сусідні фігурки
(на старті кут фіксований).
Усі висоти й швидкості задаються в `config/default.yaml`.

## Захват

❓ **Рішення ще не прийняте**, це задача першого тижня. Варіанти:

| Варіант | Плюси | Мінуси |
| --- | --- | --- |
| xArm Gripper (паралельний) + **власні 3D-друковані пальці** | надійно тримає дерев'яну фігурку | потрібен простір між фігурками для пальців |
| Вакуумна присоска (xArm Vacuum Gripper) | не потрібен простір збоку | фігурка мала й неплоска, присоска може не тримати |
| Магніт + металеві шайби під фігурками | дуже надійно, просто | треба модифікувати фігурки бота (25 шт.) |

Рекомендація: почати з паралельного захвату з вузькими пальцями. Якщо фігурки стоять надто щільно,
спробувати магніт. CAD пальців лежатиме в [`hardware/`](../hardware/).

## Код

```text
src/rootbot/robot/
├── arm.py         # ArmInterface (протокол), XArm (через SDK), MockArm (лог у консоль / файл)
├── transforms.py  # board_mm → base_mm, з калібрування
└── pick_place.py  # pick(), place(), move_piece(), go_home(); перевірка меж робочої зони
```

- **Увесь** код поза `robot/` працює з `ArmInterface`, а не з SDK напряму. Так можна запускати все з `MockArm`.
- Будь-яку точку перед рухом перевіряємо на потрапляння в дозволену зону (bounding box стола).
  Якщо точка поза зоною, кидаємо виняток **до** руху.
- Кожен виклик SDK повертає код. Ненульовий код означає помилку: зупинка, лог, повідомлення оператору.
