# 0001. Один репозиторій з модулями замість git-сабмодулів

- **Статус:** прийнято
- **Дата:** 2026-10-22

## Контекст

Проєкт має чотири частини: зір, ігрова логіка, робот, інтеграція. Ці частини можна було б винести в окремі
репозиторії й підключити як git submodules. Команда має 3–4 людини, проєкт триває ~2 місяці (до 14.12.2026).

## Рішення

Один репозиторій, один Python-пакет `rootbot` з підпакетами `common`, `game`, `vision`, `robot`, `app`.
Межі між модулями тримаємо **інтерфейсами в коді** (див. [architecture.md](../architecture.md)), а не репозиторіями.

## Чому

- Більшість задач на етапі інтеграції зачіпає 2–3 модулі одночасно. В одному репозиторії це **один PR**.
  Із сабмодулями це кілька PR плюс оновлення вказівника сабмодуля.
- Сабмодулі мають відомі «граблі»: detached HEAD, забутий `git submodule update`, конфлікти вказівників.
  На них іде час, а користі для команди з 4 людей мало.
- Один CI, одні тести, одна дошка задач, одна версія залежностей.
- Розділити репозиторій пізніше легко, а злити назад важко.

## Наслідки

- Хто за що відповідає, видно з `.github/CODEOWNERS`: GitHub автоматично просить рев'ю власника модуля.
- `game` не імпортує `vision`, `robot` чи `app`. `vision` і `robot` не імпортують одне одного.
  Порушення ловимо на код-рев'ю.
